Oh My AIHub

One Magpie can share its own channels and use several remote Magpies at once. No AI request passes through this plugin.

This node

Saving writes this plugin's options in Magpie. The supervisor reads them when the plugin host starts; Magpie restarts the host when a plugin is installed, updated or set. Both capabilities may be on at the same time; they share one EasyTier core and one network identity.

EasyTier hostnames, virtual IPs and mapped_cidr values are routing hints, not cryptographically verified identities. A catalogue quote is self-signed with a persisted Ed25519 key. The signature proves only that the same key signed the document; it does not prove who the operator is. A changed fingerprint is shown as a warning and is never accepted silently.

Operations

This page cannot call the host (the sandbox forbids network access). Use the loopback API with the token in <magpie data>/oh-my-aihub/api-token, or the CLI: 

bun plugin/bin/ohmyaihub.ts --data <magpie config dir> status
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> share on
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> catalog publish on
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> catalog discover on
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> catalog peers
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> catalog request <node-id>
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> provider add peer-b --cidr 10.66.1.2/32 --key sk-… --port 3425
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> consumers add alice deepseek/deepseek-flash 1
bun plugin/bin/ohmyaihub.ts --data <magpie config dir> topup alice 1

Remote providers are managed one by one: each has its own loopback port, its own Gateway Key and its own status. Deleting one never touches the others. Sharing only ever exports this node's own models: a remote Magpie's models stay this node's own consumption and cannot be resold through a consumer key.

## 3. A — 视觉/交互/三字段/端口/状态邻居（PROPOSED）

### 3.1 目标信息架构：**5 页**

| 页 | 内容 | 合并自现状 |
| --- | --- | --- |
| 首页 | **仅**：网络状态、可用模型、我的共享、钱包、待办 | 总览的对外摘要，不含内部检查 |
| 发现 | 伙伴目录、模型/价格、显式信任、申请、**我的连接（Remote Magpie）** | 发现 + 我的连接 |
| 我的共享 | **自动检测可分享模型**、一次“分享这些模型”、待审批申请、已授权伙伴 | 我的共享 |
| 钱包 | 钱包/入账/证据时间线、**用量与账单**、异常审计 | 测试网钱包 + 用量与账单 |
| 网络 | **首次仅三字段**；**只读诊断**（端口/邻居）；能力说明 | 网络与设置 |

- **首页不显示端口、不显示引擎内部检查**（ACL/401/目录/转发等）；这些只在“网络 → 诊断”只读展示。
- **首页的“网络状态”只给对外结论**（已连接/邻居数量摘要/待办），点击进入网络诊断。
- 不保留独立的“我的连接”“用量与账单”“网络与设置”三个旧导航；内容并入上表。
- 端口**仅在网络诊断可见，不可编辑**；端口由插件自动分配/持久化。

### 3.2 首次配置只问三个字段

- **网络名称**
- **网络密钥**
- **初始节点**（可选：若为空则插件生成/接受监听；不再要求用户先理解“接受连接/监听地址”）

角色、端口、目录端口、查询端口、RPC 端口由插件自动分配/持久化；**不提供端口编辑**。
**所有节点天然发现 + 消费**；分享不是角色开关：不分享也能发现/消费。
**我的共享没有“共享开关 + 目录发布”两个常规动作**：插件自动检测有价本机模型；用户选择一个模型集合，点一次 **“分享这些模型”**，插件自动发布目录并开放授权路径。停止分享是单独的“停止分享”确认（不再拆成开关/发布两步）。

### 3.4 A 的不变式

- 不自动分享；不自动信任；不自动批准；不自动发 Key。
- 三字段之外不要求普通用户填写角色/端口；端口不可编辑。
- 首页只显示网络状态、可用模型、我的共享、钱包、待办；**不显示端口、引擎内部检查、ACL 细节**。
- 邻居是路由提示，不是身份；不得把邻居/端口显示成“已授权”。
- 我的共享不提供“共享开关 + 目录发布”常规动作；只有一次明确的“分享这些模型”（以及单独的停止分享）。
- 保留价格未锁定、真实资产未开放、未知≠0 等提示；可折叠但默认可见结论。
- 5 页不减少安全确认次数；只减少导航与配置负担。

## 4. B — 无文件 P2P / 人工审批 / 端到端加密授权（PROPOSED）

### 4.1 目标流程（替换文件往返）

```mermaid
sequenceDiagram
  autonumber
  participant C as 使用方控制台
  participant ET as EasyTier 覆盖网
  participant P as 提供方控制台
  participant M as 使用方 Magpie

  C->>ET: connection_request（覆盖网内，结构化，不含 Key）
  ET->>P: 请求到达提供方独立有限控制服务
  P->>P: 人工核对身份/模型/额度 → 明确批准
  P-->>C: 端到端加密的 authorization（只有使用方会话可解）
  C->>C: 解密、核对身份/模型/额度、写入本地
  C->>M: 注册原生 Remote Magpie（Key 只在本机）
  M-->>C: 模型/额度回读 → 本地状态 registered
  C-->>P: ACK（registered；可延迟）
  P->>P: 未收到 ACK → 有限幂等重发/恢复；不重复造 Key
```

- **所有节点都有独立有限控制服务**：不只分享节点；任何已配置节点都能接收 `connection_request` 与 `authorization`（不分享时只能拒绝“无共享模型”，但仍可接收/回应）。分享只决定是否发布模型/开放授权路径，不决定控制服务是否存在。
- **独立有限控制服务**：只处理请求/审批/授权/ACK，不是 Magpie 管理面、不是 AI 网关、不是第二计费点；只开放在覆盖网内，Inbound 仍 Drop；限并发/限长/限速。
- **首次/身份变化仍人工 TOFU**：使用方必须核对完整指纹并显式接受；提供方批准时再次核对当前报价/身份。
- **没有文件**：`connection_request` 和 `authorization` 都是覆盖网内的结构化消息；不生成下载/上传文件。
- **E2E 加密**：授权只对使用方本次会话的临时公钥加密；提供方也不能把 Key 写给第三方。
- **人工审批**：提供方选择模型 + 填正额度 + 明确勾选；无自动批准、无自动发 Key。
- **ACK 不是注册的前置门**：使用方解密并成功注册原生 Remote Magpie、回读模型/额度后即进入 `registered`；ACK 可延迟/丢失，不得让业务状态卡在 ACK 循环。
- **ACK 丢失可恢复**：允许有界、幂等的重发/状态查询/恢复（同一 request/authorization id），不重造 Key、不重复扣费；重放由一次性 nonce + 幂等键拒绝。
- **状态与幂等**：`requested → approved → delivered → registered → acked` 是业务状态；ACK 只是投递确认。任何“未知”都必须能通过同 id 查询/重试恢复，不能“一律不重试”造成不可恢复。
- **紧急兼容**：现有申请/授权文件保留，但只在控制服务不可用时由用户显式选择；不得作为默认或验收替代。

### 4.2 加密、身份与恢复（设计约束，待安全评审）

| 项 | 约束 |
| --- | --- |
| 传输 | EasyTier 覆盖网内；不新增中心服务器/DHT/mDNS |
| 控制服务 | 所有节点常驻的独立有限服务；不是 Magpie 管理面/AI 网关 |
| 会话密钥 | 每请求临时密钥对（X25519 或 P-256 ECDH）+ HKDF + AEAD（AES-256-GCM） |
| 身份 | 绑定目录 Ed25519 公钥/指纹 + 人工 TOFU；不是“连上即信任” |
| 审批绑定 | 批准绑定 request hash、提供方身份、报价 hash、模型集合、正额度、过期时间 |
| 授权加密 | 只加密给使用方临时公钥；提供方控制台不长期保存明文 Key |
| ACK/恢复 | ACK 幂等；缺失时按同 id 有界重发/查询；不重造 Key、不重复计费 |
| 注册状态 | 以“原生 Remote Magpie 注册成功 + 模型/额度回读”为准，不以 ACK 为准 |
| 重放 | 一次性 nonce + 幂等键 + 过期；已消费授权不可复用 |
| 失败 | 解密/身份/报价/额度任一不匹配 → 拒绝；可恢复的未知走同 id 查询/重试 |

## 5. C — 钱包与主网准备（PROPOSED）

### 5.1 目标能力

- **56/8453 只读网络平权**：与测试网同形展示、同一注册表、无 primary；但**只读**，不扫描、不入账、不发交易。
- **用户收款网络默认空选**：不自动选择链/资产；必须明确选择。
- **严格资产身份**：`chainId + tokenContract + decimals + issuerType` 四元组校验；白名单；拒绝符号推断/任意代币。
- **隔离模拟钱包**：创建/恢复/锁定/敏感导出在隔离/模拟环境完成；**不声称生产级安全**，不接真实资金。
- **助记词导出必须重新验证钱包密码**：不是点一下直接显示；失败/取消不导出。
- **多扩展明确选择**：检测到多个浏览器钱包扩展时必须由用户明确选择；不自动挑、不自动切链。
- **P2P 付款/签名**：内置或外置钱包**直接签名**；**普通钱包没有签名文件路径**（旧文件签名仅高级兼容，不作为常规 UI）。
- **自动充值策略**：策略/上限/暂停/审批条件可配置；可在隔离/测试网执行；**主网禁止执行**。
- **内置钱包**：开发创建/恢复/锁定/敏感导出能力；明确标注“非生产级安全”，默认不承载真实资产。

### 5.2 目标流程

```mermaid

  W1 -->|内置| W2["隔离/模拟：创建/恢复/锁定"]
  W1 -->|外置| W3["检测扩展 → 用户明确选择一个"]
  W2 --> W4["敏感导出/助记词：重新验证钱包密码"]
  W3 --> W5["P2P 付款/签名：直接签名，无签名文件"]
  W4 --> W6["仅测试网/模拟链可入账"]
  W5 --> W6
  W6 --> W7["最终性 → 现有账本/Key 路径（测试网）"]
  W6 --> W8["56/8453：只读展示；不发送、不入账、不授信"]
  W9["自动充值策略：上限/暂停/条件"] --> W6
  W9 --> W8
```

### 5.3 C 的红线

1. **主网 56/8453**：只读网络平权；不广播交易、不扫描入账、不抬 Key cap、不执行自动充值。
2. **真实资金 NO-GO**：内置钱包不声称生产级安全；敏感导出/助记词有明确警告并重新验证密码；默认不承载真实资产。
3. 不保存明文私钥/助记词到状态/日志/页面；密钥存储/导出方案单独安全评审。
4. 不自动选择链/资产/扩展；收款网络默认空选。
5. 普通钱包不提供签名文件路径；P2P 付款/签名必须走内置或用户明确选择的外置钱包。
6. 不把测试网/模拟链结果写成主网付款或主网授信。
7. 不因收到转账自动解除暂停；不自动再签发。
8. 多扩展必须用户明确选择；**不得用 fake provider 单测声称真实 MetaMask/Rabby 兼容**；真实扩展验收当前 BLOCKED/UNKNOWN。

## 6. D — 真实资金独立审查（PROPOSED）

D 不是实现工作流，也不负责版本/时钟/峰谷价（那些是 P0）。D 在 C 的钱包/主网准备完成后，由**独立于实现者的审查代理**产出 **NO-GO 清单**；**本阶段不执行真实资金**，也不把“GO”作为本阶段产出。

```mermaid
flowchart LR
  D1["C 的钱包/主网准备完成"] --> D2["独立审查代理：代码/威胁模型/证据"]
  D2 --> D3["产出 NO-GO 清单 + 阻塞项"]
  D3 --> D4["真实资金保持禁止；本阶段不执行"]
```

审查范围：内置钱包密钥存储/助记词重新验证/导出、扩展选择与签名、P2P 付款归属、自动充值策略、主网只读边界、账本/Key 回读、失败关闭、日志/快照泄漏、平台差异。D **不得**自己改代码；只出审查报告与阻塞清单。

## 10. 失败、回滚与发布边界

| 工作流 | 失败表现 | 回滚 |
| --- | --- | --- |
| A | 布局/文案/测试断言回归 | 仅回滚 CSS/HTML/渲染，不动业务 |
| B | 解密/身份/报价/额度失败 | 拒绝请求；不落 Key；保留旧连接 |
| B | ACK 丢失/控制服务不可用 | 同 id 有界恢复；必要时用户显式选择紧急文件回退 |
| C | 主网发送/授信被触发 | 硬拒绝；不产生交易/账本/Key 变更 |
| C | 内置钱包/导出风险 | 锁定/清空会话；保留审计；不声称生产级 |
| D | 审查发现风险 | 真实资金保持 NO-GO，输出清单 |

- 不合并 PR 是**调度约束**，不是用户对产品的明文要求。
- A/B 不引入数据迁移；C 新增字段必须向后兼容 `ledger.sqlite`/`chain.sqlite`/`networks.json`。
- 所有新增动作：白名单名、字段白名单、输入上限、幂等语义、负向测试、敏感输出遮盖。
- 所有新增状态：未知/失败与“零/正常”分开显示；不得用绿色表示未证实。
